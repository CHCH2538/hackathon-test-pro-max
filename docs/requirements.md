# Requirement: ผู้ช่วยบริการรัฐแบบแชท (Bangkok Flow Hackathon)

Nov 25, 2026 · @Mobile

## ภาพรวม

เว็บแชทจุดเดียวที่รับคำถามว่า "อยากทำอะไร" แล้วตอบกลับเป็น Checklist เอกสาร + แผนการเดินทาง (ไปที่ไหน วันไหน อย่างไร) ครอบคลุมบริการรัฐหลายหน่วยงาน งานที่เว็บทำไม่ได้ (แจ้งเตือน ติดตามเคส นัดล่วงหน้า) ส่งต่อเป็น Case ไปที่ LINE OA

**ปัญหาที่แก้:** คนเสียเวลาเพราะ (1) ไม่รู้ว่าต้องไปหน่วยงานไหน โดยเฉพาะงานที่ขึ้นกับเขตอำนาจ เช่น แจ้งความต้องไป สน. ท้องที่เกิดเหตุ (2) เอกสารไม่ครบต้องไปซ้ำ (3) ไปผิดวัน/ผิดเวลา เจอคิวยาวหรือเคาน์เตอร์ปิด (4) ไม่รู้ว่าทำออนไลน์ได้อยู่แล้ว

**เป้าหมาย (Bangkok Flow):** ลดจำนวนเที่ยวที่ไม่จำเป็น และลดเวลาต่อเรื่องของประชาชน วัดเป็นชั่วโมงที่คืนให้ประชาชน

**ผู้ใช้หลัก**

- ประชาชนทั่วไปในกรุงเทพฯ ที่ต้องติดต่อราชการไม่บ่อย จึงจำขั้นตอนไม่ได้
- ผู้สูงอายุ / ลูกหลานที่ทำเรื่องแทน (ต้องรองรับการมอบอำนาจ)
- คนต่างจังหวัดที่ทำงานในกรุงเทพฯ (ทะเบียนบ้านอยู่ต่างจังหวัด)
- ชาวต่างชาติ (ระยะต่อไป)

**X-02 นอกขอบเขต:** ไม่ยื่นคำร้องแทนผู้ใช้ ไม่เก็บสำเนาเอกสารส่วนตัว ไม่ให้คำปรึกษาทางกฎหมาย ระบบเป็นผู้ช่วยวางแผนและส่งต่อไปยังช่องทางทางการ

## User journey ตัวอย่าง

ทุก journey จบด้วยผลลัพธ์ 3 อย่าง: Checklist เอกสาร, แผน (ไปที่ไหน วันไหน เดินทางอย่างไร) และปุ่ม "ส่งเข้า LINE" เพื่อรับแจ้งเตือน

**J1 — แจ้งความ (กระเป๋าถูกขโมยที่สยาม)**

1. ผู้ใช้พิมพ์ "กระเป๋าตังค์หายแถวสยาม บัตรประชาชนอยู่ข้างใน"
2. ระบบถามคำถามคัดแยก: หายหรือถูกขโมย? เกิดตรงไหน (ปักหมุดบนแผนที่)? มีบัตรเครดิต/บัตร ATM หายด้วยไหม?
3. ระบบตอบ: คดีนี้ไม่ใช่อาชญากรรมทางเทคโนโลยี ต้องไป สน. ท้องที่ + ชื่อ สน. จากจุดที่ปัก + เบอร์โทร + เส้นทาง
4. Checklist: สิ่งที่ต้องทำก่อนไป (อายัดบัตรธนาคาร) + เอกสารที่ต้องเตรียม + ข้อมูลที่ต้องจำ (เวลา สถานที่ รายการของหาย)
5. แผนต่อ: หลังได้บันทึกแจ้งความ → ทำบัตรประชาชนใหม่ที่เขต (ต่อเป็น J3 อัตโนมัติ)
6. ส่ง Case เข้า LINE OA → เตือนขั้นต่อไปตามวันที่เลือก

**J1b — โดนหลอกโอนเงินออนไลน์:** ระบบพาไป thaipoliceonline.go.th / สายด่วน 1441 พร้อม Checklist หลักฐาน (สลิป แชท เลขบัญชีปลายทาง) ไม่ต้องเดินทาง

**J2 — ต่อใบขับขี่**

1. "ใบขับขี่หมดเดือนหน้า ต้องทำไง"
2. ระบบถาม: ประเภทใบขับขี่? หมดอายุเกินกี่ปี? สะดวกสำนักงานขนส่งไหน?
3. แผนเป็นลำดับ: อบรมออนไลน์ → ยืนยันตัวตน ThaID → จองคิว DLT Smart Queue (ลิงก์ไประบบจริง) → ไปสำนักงานตามนัด
4. ผู้ใช้กรอกวันที่จองได้กลับมาในแชท → LINE OA เตือนก่อนวันนัด 1 วัน และเช้าวันนัด พร้อม Checklist และเวลาออกจากบ้าน

**J3 — ทำบัตรประชาชนใหม่ (บัตรหาย)**

1. ระบบถาม: อยู่ใกล้ที่ไหน? สะดวกวันไหน/ช่วงเวลาไหน? มีบันทึกแจ้งความแล้วหรือยัง?
2. เสนอ 2–3 เขตที่เดินทางสะดวก (ใกล้ BTS/MRT) พร้อมช่วงเวลาที่คนน้อย → ลิงก์จอง BMA Q
3. LINE OA เตือนวันนัด + เตือนเมื่อฝนหนัก/รถติดผิดปกติในเส้นทาง (ระยะต่อไป)

| W-12 | เก็บ Case ได้โดยไม่ต้องสมัคร (anonymous session) และเปิดกลับมาดูได้ผ่านลิงก์ | S |

## Functional requirements — วางแผนเดินทาง (Google Maps Platform)

แผนทุกแผนต้องตอบได้ว่า "ไปสำนักงานไหน ออกจากบ้านกี่โมง ไปทางไหน" โดยใช้ Google Maps Platform เป็นแหล่งข้อมูลพิกัด เส้นทาง และเวลาเดินทาง

| ID | Requirement | Google API | P |
| --- | --- | --- | --- |
| T-01 | แปลงชื่อสถานที่ที่พิมพ์ (จุดเกิดเหตุ, จุดต้นทาง) เป็นพิกัด ด้วย autocomplete ที่จำกัดพื้นที่กรุงเทพฯ | Places API (New) Autocomplete + Place Details, Geocoding API | M |
| T-02 | คำนวณเส้นทางจากจุดต้นทางไปสำนักงาน 4 โหมด: ขนส่งสาธารณะ, รถยนต์, มอเตอร์ไซค์, เดิน แสดงเวลา ระยะทาง และขั้นตอน (สาย BTS/MRT/รถเมล์ จุดต่อรถ) | Routes API — Compute Routes (TRANSIT / DRIVE / TWO\_WHEELER / WALK) | M |
| T-03 | คำนวณ "เวลาที่ควรออกจากบ้าน" จากเวลานัด: ขนส่งสาธารณะใช้ arrivalTime, รถยนต์ใช้ departureTime + traffic-aware บวก buffer (หาที่จอด / เดินเข้าอาคาร) → ใช้ในแจ้งเตือน L-02 | Routes API — Compute Routes (TRAFFIC\_AWARE) | M |
| T-04 | เปรียบเทียบสำนักงานที่เลือกได้หลายแห่ง (เช่น 3 เขต, 2 สำนักงานขนส่ง) เรียงตามเวลาเดินทางจริง ไม่ใช่ระยะทางตรง → ใช้ใน W-07 | Routes API — Compute Route Matrix | M |
| T-05 | แสดงแผนที่บนเว็บ: หมุดสำนักงานที่แนะนำ จุดต้นทาง และเส้นทาง (polyline) ปักหมุดจุดเกิดเหตุได้บนแผนที่เดียวกัน (W-06) | Maps JavaScript API | M |
| T-06 | ปุ่ม "นำทางใน Google Maps" ทั้งบนเว็บและใน Flex Message ของ LINE เปิดแอป Google Maps พร้อมปลายทางและโหมดเดินทาง | Maps URLs (deep link) | M |

**ข้อกำหนดประกอบ**

- **T-C1 ต้นทุน:** Google Maps คิดเงินตาม SKU แต่ละ SKU มีโควตาฟรีรายเดือนของตัวเอง (Essentials 10,000 ครั้ง, Pro 5,000 ครั้ง — [pricing categories](https://developers.google.com/maps/billing-and-pricing/pricing-categories)) คำขอที่ใช้ TRAFFIC\_AWARE ถูกคิดเป็น Pro ([Routes API billing](https://developers.google.com/maps/documentation/routes/usage-and-billing)) → ใช้ traffic-aware เฉพาะตอนคำนวณเวลาออกจากบ้าน (T-03, T-08) ส่วนการเปรียบเทียบสำนักงานใช้ Essentials
- **T-C2 ควบคุมค่าใช้จ่าย:** ใช้ field mask ขอเฉพาะ field ที่ใช้, ตั้ง quota และ budget alert ใน Google Cloud, ปุ่มนำทางใช้ Maps URLs แทนการเรียก API
- **T-C3 ความเป็นส่วนตัว:** จุดต้นทางมักเป็นบ้านผู้ใช้ → เก็บผูกกับ Case เท่านั้น ลบพร้อม Case (N-03) และไม่ส่งพิกัดเข้า LLM
- **T-C4 เงื่อนไขการใช้งาน:** แสดง attribution ของ Google ตามที่กำหนด และตรวจเงื่อนไขการ cache ผลลัพธ์ใน Google Maps Platform Terms ก่อน cache เส้นทาง
- **T-C5 ความครบของข้อมูลขนส่งสาธารณะ:** ต้องทดสอบว่าโหมด TRANSIT ในกรุงเทพฯ ครอบคลุมรถเมล์และเรือแค่ไหน ถ้าไม่พบเส้นทาง ให้แสดงเส้นทางรถยนต์/มอเตอร์ไซค์แทน

**ข้อจำกัดที่ต้องออกแบบรองรับ**

- **L-C1** LINE นับ push message เป็นโควตารายเดือน ส่วน reply message ไม่นับ ([LINE Developers](https://developers.line.biz/en/tips/2026/05/28/how-to-count-messages/)) แต่ LINE ประเทศไทยจะเริ่ม[คิดเงิน Reply API เกิน 25,000 ข้อความ/เดือน ตั้งแต่ ก.พ. 2027](https://www.relevantaudience.com/social-media-marketing/line-reply-api-25000-free-messages-agency-global-platform/) → รวมแจ้งเตือนหลายเรื่องเป็นข้อความเดียว และตั้งเพดานจำนวน push ต่อ Case
- **L-C2** push ได้เฉพาะผู้ใช้ที่เพิ่ม OA เป็นเพื่อน → W-11 ต้องพาผู้ใช้กดเพิ่มเพื่อนก่อนผูก Case
- **L-C3** LINE OA ห้ามรับแจ้งความหรือเอกสารทางการ ทุกข้อความที่เกี่ยวกับคดีต้องมีประโยค "ระบบนี้ไม่ใช่ช่องทางรับแจ้งความ"

**D-10 สถานะ Case:** วางแผนแล้ว → นัดแล้ว → ถึงวันนัด → เสร็จ (หรือ เลื่อน → นัดแล้ว, ยกเลิก ได้ทุกจุด)

## Tech stack และ Security

วัน Hackathon ใช้ stack ที่ได้ HTTPS, ฐานข้อมูล, และการคุมสิทธิ์ระดับแถวมาพร้อมในตัว (Next.js + Supabase + Vercel) เพื่อให้เวลา 8 ชั่วโมงไปอยู่กับฟีเจอร์ ถ้าชนะค่อยย้ายส่วนหลังบ้านไป ASP.NET Core ที่ทีมถนัดและควบคุมได้มากกว่า ส่วน OWASP ทำตั้งแต่ prototype ตามตารางด้านล่าง

| Layer | Hackathon (8 ชม.) | Production (ถ้าชนะ) |
| --- | --- | --- |
| Web + API | Next.js (App Router) โค้ดเดียวทั้ง UI และ API routes | Next.js (เฉพาะ UI) + ASP.NET Core 8 Web API |
| Hosting | Vercel (HTTPS อัตโนมัติ) | Cloud ที่มี region ใกล้ไทย หรือคลาวด์ภาครัฐถ้าได้พันธมิตรรัฐ + WAF/CDN |
| Database | Supabase Postgres + PostGIS (point-in-polygon) + Row Level Security | Managed PostgreSQL + PostGIS หรือ SQL Server (geography type) |
| AI | Claude API ผ่าน server route, tool use เลือก serviceId | Claude ผ่าน AWS Bedrock (คุม IAM, logging, data residency) |
| LINE | Messaging API webhook เป็น API route + LINE Login | แยก service + queue |
| Maps | Places Autocomplete, Route Matrix, Maps URLs | + Routes Pro (Phase 2) |
| Reminder | ปุ่มเพิ่มลงปฏิทิน (W-17) ไม่ต้องมี scheduler | Hangfire / queue + worker |
| ทางเลือก | ถ้าทีมถนัด N8N ใช้ต่อ LINE ↔ Claude ได้ แต่ต้องตรวจ signature และเก็บ secret ใน credentials เท่านั้น | ย้าย logic เข้า API หลัก |

**แผน 8 ชั่วโมง**

1. 0:00–0:30 — ตั้ง repo, deploy หน้าเปล่า, ใส่ env secrets, จำกัด API key, เปิด RLS + security headers ตั้งแต่แรก
2. 0:30–2:00 — seed catalog 5 บริการ + สำนักงาน + polygon สน. นำร่อง, หน้าแชท
3. 2:00–4:00 — Claude: แยก intent, ถามคัดแยก, แสดง Checklist จาก DB
4. 4:00–5:30 — Google Maps: autocomplete, เทียบสำนักงาน, ปุ่มนำทาง, ปุ่มเพิ่มลงปฏิทิน
5. 5:30–6:30 — LINE OA: webhook + ตรวจ signature, ผูก Case, Flex Message
6. 6:30–7:15 — Security pass: ไล่ checklist OWASP ด้านล่าง, ลอง prompt injection 10 แบบ, สแกน OWASP ZAP baseline, npm audit
7. 7:15–8:00 — freeze code, ซ้อม demo 3 flow, สไลด์

## Roadmap: Phase 1 และ Phase 2

Phase 1 ให้ประชาชนใช้ฟรีครบทุกเรื่องที่ช่วยลดเที่ยว โดยออกแบบให้ต้นทุนอยู่ในโควตาฟรีของ LINE และ Google Maps ส่วน Phase 2 เพิ่มฟีเจอร์ที่มีต้นทุนต่อผู้ใช้ โดยเฉพาะ push แจ้งเตือนและเส้นทางตามจราจรจริง

เส้นแบ่งมาจากต้นทุน: LINE ไม่นับ reply message แต่นับ push และ Routes API แบบดูจราจรจริงคิดเป็น Pro SKU Phase 1 จึงใช้ LINE แบบผู้ใช้ทักมาก่อน และใช้เวลาเดินทางทั่วไปแทน (หมายเหตุ: LINE ไทยจะเริ่มคิดเงิน reply เกิน 25,000 ข้อความ/เดือน ตั้งแต่ ก.พ. 2027)

**Requirement ใหม่ใน Phase 1**

- **W-17 เพิ่มลงปฏิทิน:** ปุ่มสร้างนัดใน Google Calendar (ลิงก์) หรือไฟล์ .ics สำหรับ iPhone/Outlook ใส่เวลาออกจากบ้าน ที่อยู่ ลิงก์นำทาง และ Checklist ในรายละเอียดนัด ตั้งเตือนล่วงหน้า 1 วัน → ผู้ใช้ได้แจ้งเตือนจากปฏิทินของตัวเองโดยระบบไม่มีต้นทุน (M)

**ข้อเสนอเพิ่มเติมสำหรับ Phase 2**

- **P2-01 กระเป๋าเอกสาร:** ผู้ใช้บันทึกวันหมดอายุเอกสารหลายรายการไว้ที่เดียว (บัตรประชาชน ใบขับขี่ ภาษีรถ พาสปอร์ต) เก็บแค่ประเภทกับวันที่ ไม่เก็บเลขเอกสาร
- **P2-02 ดูแลแทนครอบครัว:** ลูกหลานตั้ง Case และรับแจ้งเตือนแทนผู้สูงอายุ พร้อม Checklist กรณีมอบอำนาจ
- **P2-03 คาดการณ์ช่วงคนน้อย:** ให้ผู้ใช้รายงานเวลารอจริงหลังเสร็จธุระ (1 คำถาม) แล้วนำมาแนะนำวันและช่วงเวลาใน W-07
- **P2-04 เชื่อมระบบรัฐ:** ถ้าได้ความร่วมมือ ดึงคิวว่างจาก BMA Q / DLT มาแสดงตรง แทนการลิงก์ออก

## Business model: จ่ายเป็นครั้ง ไม่ใช่จ่ายทุกเดือน

แนะนำแบบผสม: ใช้ฟรี (Phase 1) + ซื้อ **Plan Pass เป็นครั้ง** สำหรับเรื่องที่อยากให้ช่วยตามให้จบ + **แพ็กรายปีราคาต่ำ** เฉพาะคนที่ต้องการเตือนเอกสารหมดอายุตลอดปี เพราะคนทั่วไปติดต่อราชการไม่กี่ครั้งต่อปี การเก็บรายเดือนจะทำให้ผู้ใช้รู้สึกว่าจ่ายทิ้งเปล่าและยกเลิก

| รูปแบบ | จ่ายอะไร | เหมาะกับ | ข้อดี | ข้อเสีย | คำแนะนำ |
| --- | --- | --- | --- | --- | --- |
| Subscription รายเดือน | ค่าบริการต่อเนื่อง | คนที่ติดต่อราชการบ่อย (มีน้อย) | รายได้คาดการณ์ได้ | ใช้ไม่บ่อย → ยกเลิกสูง | ไม่แนะนำ |
| **Plan Pass (จ่ายต่อ Case)** | เปิดโหมด Smart ให้ 1 Case จน Case ปิด | คนที่มีธุระเป็นครั้งคราว | จ่ายตอนที่เห็นคุณค่าชัด ต้นทุนต่อ Case คำนวณได้ | รายได้ไม่สม่ำเสมอ | ตัวหลัก |
| แพ็กเครดิต (เช่น 3 หรือ 5 Pass) | Pass หลายใบราคาต่อใบถูกลง ใช้ได้ 12 เดือน | ครอบครัว / ซื้อให้พ่อแม่ | ได้เงินก่อน แจกเป็นของขวัญได้ | ต้องมีระบบ wallet + กติกาหมดอายุ | เสริม |
| รายปีราคาต่ำ (Family) | กระเป๋าเอกสาร + เตือนหมดอายุทั้งบ้าน + Pass จำนวนหนึ่ง | คนดูแลเอกสารหลายคนในบ้าน | คุ้มค่าเพราะงานเตือนหมดอายุเกิดตลอดปีจริง | ต้องมีฟีเจอร์ P2-01/02 ก่อน | เสริม หลัง P2-01 |
| องค์กร/สปอนเซอร์จ่าย (B2B/B2G) | ซื้อ Pass เป็นก้อน แจกเป็นโค้ด | สวัสดิการพนักงาน, กลุ่มเปราะบาง | ประชาชนไม่ต้องจ่ายเอง | ต้องขายทีละองค์กร | ช่องทางคู่ขนาน |

**หลักการตั้งราคา**

- **BP-01** คำแนะนำพื้นฐานที่ช่วยให้ไม่เสียเที่ยว (Checklist, หน่วยงานที่ต้องไป, เส้นทาง, เพิ่มลงปฏิทิน) **ฟรีตลอด** เก็บเงินเฉพาะความสะดวกที่มีต้นทุนจริง → ลดคำตำหนิว่าเก็บเงินค่าบริการรัฐ
- **BP-02** สิ่งที่ได้ใน Plan Pass (โหมด Smart ต่อ 1 Case): push เตือนทุกขั้น (L-02), เวลาออกจากบ้านตามจราจรจริง + คำนวณใหม่เช้าวันนัด (T-03, T-08), ต่อขั้นถัดไปอัตโนมัติ (L-06), รวมหลายธุระ (W-09, T-07), เตือนเหตุพิเศษ (L-08)
- **BP-03** ตั้งราคาจากต้นทุนต่อ Case (จำนวน push × ค่า LINE + จำนวน Routes Pro + token LLM) คูณส่วนเผื่อ และเทียบกับค่าเดินทางเที่ยวเดียวที่ผู้ใช้ประหยัดได้ → ราคา Pass ควรต่ำกว่าค่าเดินทาง 1 เที่ยวชัดเจน (ตัวเลขจริงต้องทดสอบกับผู้ใช้)
- **BP-04** Case แรกของผู้ใช้ใหม่ได้โหมด Smart ฟรี 1 ครั้ง เพื่อให้เห็นความต่างก่อนตัดสินใจซื้อ
